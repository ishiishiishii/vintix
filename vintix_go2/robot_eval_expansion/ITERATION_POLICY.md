# 専門家 PPO のイテレーション設定

更新: 2026-11-25（日本時間）

## 結論（どうするか）

1. **初回は 301 iter・保存間隔 20**（現状どおり）。まず一度最後まで走らせる。
2. **判定は学習ログの平均長ではなく、決定論的な品質評価**（完走 ≥95% かつ指令速度の **≥80%**。`EXPERT_QUALITY.md` と揃える）。
3. 品質を満たさないときだけ、次で分岐する。
   - **終盤まで平均長・報酬が上がり続けている** → 同じ設定のまま **301 → 601 → 最大 901** と延長（直前の ckpt から再開可）。
   - **途中で平均長が崩れている** → イテレーションを増やしても直らないことが多い。ピーク付近の ckpt を評価し、直らないなら URDF・初期姿勢・PD・高さ・報酬を直す（B1 / Laikago で何度も起きたパターン）。
4. Isaac Lab の Spot は **数千〜数万 iter**（例: 公開 cfg で最大 35000、NVIDIA ブログ例は 15000・4096 env）だが、シミュ・報酬・ステップ定義が違うので **数字をそのままコピーしない**。参考にするのは「難しい機体は 301 では足りないことがある」という事実だけ。

## なぜ 301 だけでは足りない可能性があるか

| 根拠 | 内容 |
|------|------|
| 本リポジトリ | Go2 / Aliengo（MorFiC URDF）などは 301 で品質条件を満たす例がある |
| 本リポジトリ | B1 は 301 の途中で崩れ、**密保存＋ピーク ckpt** が必要だった。長いほど良いわけではない |
| Isaac Lab Spot | 平地歩行でも **15000 iter 規模**の報告あり（4096 env） |
| RaisimGym / Laikago 系論文 | 最大 **1000 iter** 前後で学習する例あり |
| #10 Body PPO | 端点の切り分けは **500 iter** を使った |

つまり「足りない機体もある」は妥当。ただし **足りない＝すぐ 15000 にする**のではなく、上の分岐で増やす。

## 運用ルール（拡充ロボット）

| 段階 | `max_iterations` | `save_interval` | やること |
|------|------------------|-----------------|----------|
| A. 初回 | **301** | **20** | 学習 → `eval_expert_quality.py` |
| B. 曲線が上昇中で未達 | **601** | 20 | 再開または最初から。再評価 |
| C. まだ上昇中で未達 | **901** | 20 | ここまでを「学習不足」の上限とする |
| D. 901 でも未達、または途中崩壊 | （増やさない） | — | URDF／初期姿勢／PD／高さ／指令を文献（Isaac Lab・RaisimGym・MorFiC）に合わせて直す |

補足:

- 指令だけ下げて「指令比 ≥95%」を通すのは、学習不足の切り分けには使わない（条件操作になる）。
- 延長するときは **中間 ckpt も全部残す**（崩れた最終 iter を使わない）。
- 時間の目安（このマシン・4096 env）: 301 ≈ 20–50 分、601 ≈ 40–100 分、901 ≈ 1–2.5 時間。
- **再開時の `--max_iterations`:** いまの rsl_rl は `learn(n)` が **現在 iter + n**。例: 300 まで終わったあとに 601 へ伸ばすなら `--max_iterations 301`（601 を渡すと 901 まで走る）。表示が `300/601` になれば正しい。

## Spot / Laikago への当てはめ

- **Spot:** 参照は **Isaac Lab SpotFlat**（init z≈0.5、公式 runner は長め）。初回 301 で品質未達かつ曲線上昇なら 601→901。
- **Laikago:** 参照は **RaisimGym**（init z≈0.46、観測平均高さ≈0.44、kp=40 / kd=1）と関連論文（kp=40、最大≈1000 iter）。GenLoco の動作模倣用 PD は使わない。初回から崩壊している場合は iter 延長より URDF・姿勢・PD を先に直す。
