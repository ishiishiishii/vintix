# 指標の対応表（本線 vs 比較手法）

Issue: [#22](https://github.com/ishiishiishii/vintix/issues/22)  
更新: 2026-11-23（autopilot）

論文・社内メモで「同じ表に並べる」ときに、何が同じで何が違うかを明示する。

## 本線（Vintix / Genesis 速度追従）でよく使うもの

| 名前 | 意味 | 典型的な値 |
|------|------|------------|
| 完走率（Success / completion） | エピソードが時間切れまで転倒せず終わった割合 | 0–100% |
| 平均エピソード長 | 転倒までの平均ステップ数（上限あり） | 例: 上限 500 |
| 速度追従の良さ | 指令速度と実速度の近さ（報酬や誤差） | タスク依存 |
| 平均 return | エピソード報酬の合計（または正規化） | 報酬設計依存 |

## 各手法が公式側で出しているもの

| 手法 | 公式シミュレータ | 主に報告している指標 | 本線の完走率との関係 |
|------|------------------|----------------------|----------------------|
| GenLoco | PyBullet（模倣） | 生存ステップ数、return | **別タスク**（動きの模倣）。生存≈完走の粗い代理にはなるが、速度追従の完走率とは同一視しない |
| URMA | MuJoCo（RL-X） | return、生存ステップ | 速度追従なので本線に近い。完走＝「指定ステップまで生存」と定義すれば対応可 |
| MorFiC | Isaac Gym | 公式 play の可視化／報酬 | 公式数値がこのコンテナでは未取得。Genesis 近似は参考列のみ |

## 並べ方の推奨

1. **主表**: 各手法の公式シミュレータでの「指定秒数／ステップまで生存できたか」と return
2. **参考列**: Genesis に観測を近似して載せたときの完走率（現状 GenLoco/MorFiC は 0%）
3. 脚注で「タスク・観測・シミュレータが違う」と書く

## URMA → 本線完走率への写し方（実務）

- 公式評価スクリプト: `wrappers/urma/run_urma_official_eval.py`
- いまの厚め結果: Go2・3 エピソード・各 **1000 ステップ**（公式 20 秒相当）→ すべて生存 → 完走率 **100%**（この定義・この長さに限る）
- 本線の評価が「最大 N ステップ」なら、同じ N で URMA 公式を取り直すと表が揃う

## まだ揃っていないもの

- MorFiC 公式（Isaac Gym）の数値
- 全手法を **同じロボット・同じ指令速度・同じ最大ステップ** で揃えた表（次の配線／本評価の仕事）
