# Notion 記録ページの書き方（研究の目的ごとのページ）

ユーザーの方針（原文）: もっとわかりやすくまとめられるように。結果はグラフや動画を用いて記録したり、大まかな内容と結果などをまとめた後に、トグルなどで詳細設定や詳細結果などを記載できると良い。つまり、もっとわかりやすくNotionに記録できるようにして。

追加合意（2026-11-15）: **上部は長い文章にしない。** 箇条書き・短い文・単語で「何が分かったか」が直感的に分かるようにする。実験詳細・数値の根拠・補足図はトグルに移し、**情報量は落とさない。** グラフの見た目は [figure-style.md](figure-style.md) に従う。

読み手は「ページを開いて 1 分で、何が分かって・次に何をするか」を知りたい。
上から順に **結論 → 図 → 要点 → 次 → 詳細（トグル）→ 実行ログ（トグル）** の順に並べる。

## ページの構成（この順番・この見出し）

```markdown
<callout icon="📌">
	**いまの結論:** （1〜2 文。数値入り。暫定なら「暫定（シード 2/10）」のように根拠の量を書く）
	**状態:** 実行中（境界付近 71/520、PPO 未着手）／完了　｜　**最終更新:** 2026-11-04 19:30 — （前回からの変化を 1 文）
</callout>

## 目的
- **問い:** …
- **やり方:** …（箇条書き 2〜4 行。長い背景説明は書かない）

## 主な結果
（長い段落は書かない。図の直後は箇条書き・短文・単語で「何が分かるか」が一目で分かるようにする）

![（図が示すことを短く）](https://raw.githubusercontent.com/ishiishiishii/vintix/<commit SHA>/vintix_go2/<実験>/figures/<図>.png)
- **読み方:** 横軸・縦軸・線の色・帯（平均±標準偏差）を 1 行
- **要点:** 方策ごと・軸ごとに 1 行ずつ（例: 「Vintix: 1.25×まで高完走 → 1.3×で 0%」）

<table header-row="true">（要約表。5〜8 行まで。境界の前後など大事な行だけ。強調したい数値・倍率は **太字**）</table>

（動画があればここ。「歩ける例」と「崩れる例」を並べる）

## いま言えること
- （3〜7 個。太字の見出し句 ＋ 数値。1 項目は 1 行〜短い 2 行まで）
- **まだ言えないこと:** （未切り分けを短く列挙。詳細はトグルへ）

## 次にやること・判断待ち
- （Issue 番号付き。進行中／判断待ち／任意をラベルで分ける）

## 実験設定（詳細） {toggle="true"}
	（全パラメータの表、設計の理由、使ったモデル・データ）

## 詳細結果 {toggle="true"}
	（全点の表、補足の図、シードごとの値、生データの場所。上部から移した長い説明もここへ）
	（補足図は「主図 / 補足」を明示。重要度が低い図はさらに入れ子トグルへ。図ごとに「何を示すか」を 1〜2 行）

## 実装・再現方法 {toggle="true"}
	（実験ディレクトリ、主要ファイル、実行コマンド、ブランチ、Issue）

## うまくいかなかったこと → 修正 {toggle="true"}
	（時系列で短く）

## 実行ログ
（ここだけ見出しはトグルにしない。各エントリをトグル見出しにして末尾に追記する）

### 2026-11-04 19:30 （何が分かったかを見出しにする。例「質量 1.15〜1.25 倍の Vintix はシードで大きくぶれる」） {toggle="true"}
	- **実行内容:** …
	- **結果:** …（図があれば埋め込む。表は 10 行程度まで）
	- **考察:** 言えること／まだ言えないこと
	- **次:** …（Issue 番号）
```

## 書き方のルール

- **先頭のコールアウトと「主な結果」「いま言えること」は毎回最新に書き換える**。古い結果を上に残さない
  （古い数値は「詳細結果」か実行ログへ移す）。実行ログは追記のみ。
- 実行ログの見出しは「やったこと」ではなく「分かったこと」にする。新しい結果が無い監視だけの回はページに何も書かない
  （「最終更新」の時刻だけの書き換えもしない。更新履歴が埋もれるため）。
- 数値には単位と根拠の量（シード数、エピソード数）を付ける。暫定値は「暫定」と書く。
- **上部（結論・主な結果・いま言えること）は箇条書き優先。** 長い説明文は「詳細結果」トグルへ移す（情報量は落とさない）。
- 1 段落 3 文まで（上部では段落より箇条書き）。表は要約 5〜8 行・詳細でも 15 行程度まで（それ以上は CSV のパスを書く）。
- **表では強調したいセル・数値を太字にする**（境界の落ち込み、方策間の差、結論に直結する行・列など）。全部を太字にしない。読み手が視線を止めるべき箇所だけ。
  - 例: 崖の行 `| 質量 **1.3×** | **0** | 0 | 100 | … |`、重要な列見出しや「その体の PPO は落ちない」側の数値だけ `**100**`
- 専門用語は初出で言い換える（例: Success rate / 完走率 = 1000 step 転倒せずに終わったエピソードの割合）。
- トグルの中身はすべてタブ 1 段でインデントする（インデントしないとトグルの外に出る）。`<` `>` はエスケープしない。

## 図・動画の載せ方（Notion API に画像アップロードが無いため GitHub 経由）

**図の見た目・軸・ファイル名は必ず [figure-style.md](figure-style.md) に従う**（タイトルなし、平均±帯、大きい文字、1.0 基準の目盛り、記述的ファイル名、など）。

1. 図は実験ディレクトリの `figures/` に、**内容が分かるファイル名**で保存する
   （例: `go1_mass_scale_completion_return_mean_std.png`）。PNG・おおむね 1 MB 以下。
2. `*.png` は `.gitignore` 対象なので `git add -f vintix_go2/<実験>/figures/<図>` で明示的に追加してコミット・push する
   （リポジトリは公開。載せてよい図だけを置く。`graphs/` などの自動生成物は追加しない）。
3. Notion には **コミット SHA 固定の URL** で埋め込む:
   `https://raw.githubusercontent.com/ishiishiishii/vintix/<SHA>/vintix_go2/<実験>/figures/<図>.png`
   （ブランチ名の URL だと後で図が差し替わり、過去の実行ログの図まで変わってしまうため）。
   埋め込み前に `curl -sI <URL>` で 200 と `content-type: image/png` を確認する。
4. 動画は 5〜10 秒の GIF（5 MB 以下）にして同じ方法で画像として埋め込む。MP4 は `<video src="<raw URL>"></video>`
   を試し、再生できない場合はリンクにする。代表は「歩ける例」「崩れる例」の 2 本。
5. 図は対応する表・文章の直後に置く（ページ末尾にまとめて貼らない）。
   キャプションまたは直後の箇条書きで「何が分かる図か」「軸・色・帯の意味」を書く。
6. **主図だけ上部。** 発見用・冗長な補足図は詳細トグル（必要なら入れ子）へ。

## README との対応

実験ディレクトリの `README.md` 末尾「実行ログ」には同じエントリを Markdown で書く（トグルは見出しと箇条書きにし、
図は `figures/<図>.png` の相対パスで `![](figures/...)` と埋め込む）。
