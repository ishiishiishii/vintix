# 実験設計の文献調査（必須）

ユーザー合意（2026-11-15）。実験内容・方針を決めて実装する前に、近いテーマの論文を調べ、
パラメータ・評価指標・正規化などの詳細設計を文献に裏打ちする。

## いつやるか

次のいずれかに着手する**前**（コードを書く・本番ジョブを回す前）:

- 新しい実験ディレクトリ／Issue（`experiment` / `task`）
- 既存実験の方針変更（変える物理量、指標、正規化、比較条件の追加など）
- 「こう変えるのが妥当か」が文献なしでは決められない設計判断

単なるバグ修正・図の見た目・既存パイプラインの監視だけのときは不要。

## 調査のやり方

1. **ネット上で論文を 5 本以上**調べる（arxiv / 会議論文 / 公式ドキュメント可）。
2. **テーマが近いものを優先**する。例:
   - ロボット汎化・クロスロボット適応・leave-one-out
   - 形態・質量・サイズのドメインランダマイゼーション
   - アルゴリズム蒸留 / in-context RL の評価プロトコル
   - sim-to-real での正規化・観測・報酬の扱い
3. 各論文から、少なくとも次をメモする（無い項目は「論文に記載なし」と書く）:
   - **何を変えるか**（質量・慣性・脚長・PD・摩擦など）とその範囲
   - **評価指標**（return、完走率、速度追従、成功定義など）
   - **正規化**（観測・行動・報酬、タスク平均か per-robot か）
   - **シード・試行数・環境数**などの評価プロトコル
   - 本実験との違い（目的が DR なのかゼロショット境界なのか等）
4. メモを踏まえて**本実験の設計を決める**（文献の丸写しではなく、問いとの整合で選ぶ）。
5. 採用／不採用の理由を 1〜2 文で残す。

## どこに残すか

次の**いずれか以上**に書く（情報量は落とさない）:

- 実験 Issue 本文（下の「文献調査」節）
- 実験ディレクトリの `README.md`（設計の根拠）
- 必要なら Notion の「実験設定（詳細）」トグル

最低限の表例:

| 論文 | 変える量 | 指標 | 正規化 | 本実験への採否 |
|------|----------|------|--------|----------------|
| … | … | … | … | 採用 / 参考 / 不採用（理由） |

## 完了の目安

- [ ] 近いテーマの文献が **5 本以上**
- [ ] 変えるパラメータ・指標・正規化について、文献に基づく選択理由がある
- [ ] Issue または README に調査表（または同等の箇条書き）がある
- [ ] そのうえで実装・本番に進む
